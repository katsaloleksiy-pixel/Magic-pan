# Магическая кастрюля — бот, который учится вашему стилю монтажа и монтирует по нему

**Учёба:** бот принимает ваши готовые ролики, разбирает их и показывает «паспорт стиля». Паспорт можно поправить обычным сообщением.
**Монтаж:** вы присылаете исходники — бот расшифровывает речь, убирает паузы и дубли, ставит перебивки, вшивает субтитры по паспорту и присылает готовый ролик. Правки — текстом.

## Файлы проекта

| Файл | Зачем |
| --- | --- |
| `Magic pan-server.js` | Сам бот. Внешних библиотек нет |
| `Magic pan-Dockerfile` | Сборка для Railway: бот + свой сервер Telegram Bot API + ffmpeg + шрифты |
| `Magic pan-README.md` | Эта инструкция |

## Что получить перед установкой

1. **Токен бота.** В Telegram напишите @BotFather → `/newbot`. Создайте нового бота: не используйте токен от других проектов.
2. **api_id и api_hash.** Зайдите на https://my.telegram.org под своим номером → «API development tools» → создайте приложение. Они нужны, чтобы бот принимал файлы больше 20 МБ и отправлял готовые ролики больше 50 МБ.
3. **Ключ Gemini.** https://aistudio.google.com/apikey. На бесплатном тарифе Google использует присланные материалы для улучшения своих продуктов, на платном — нет.

## Установка на Railway

1. Загрузите `Magic pan-server.js` и `Magic pan-Dockerfile` в репозиторий на GitHub (в корень).
2. Railway → New Project → Deploy from GitHub repo → выберите репозиторий.
3. В сервисе откройте Variables и добавьте:

| Переменная | Значение |
| --- | --- |
| `RAILWAY_DOCKERFILE_PATH` | `Magic pan-Dockerfile` |
| `BOT_TOKEN` | токен от @BotFather |
| `GEMINI_API_KEY` | ключ Gemini |
| `TELEGRAM_API_ID` | api_id с my.telegram.org |
| `TELEGRAM_API_HASH` | api_hash с my.telegram.org |

4. Добавьте к сервису Volume с путём `/data`. Там хранятся примеры, паспорт стиля и исходники текущего ролика; без него всё пропадёт при обновлении.
5. Публичный домен не нужен.
6. После запуска сразу напишите боту `/start`. Первый, кто это сделает, становится владельцем — остальным бот отвечать не будет.

**Обновление:** замените `Magic pan-server.js` и `Magic pan-Dockerfile` в репозитории — Railway пересоберёт бота сам. Примеры и паспорт сохранятся на Volume.

## Как пользоваться

### Учёба (/learn)
1. Пришлите боту 5–15 своих готовых роликов.
2. Нажмите «Собрать паспорт стиля».
3. Если что-то не так — нажмите «Поправить» и напишите правку: «субтитры у меня всегда жёлтые».
4. Нажмите «Всё верно» — бот перейдёт в режим монтажа.

### Монтаж (/edit)
Исходники принимаются в два этапа — так бот не тратит время и деньги на расшифровку речи там, где её не нужно разбирать.

1. **Этап «Речь».** Пришлите видео, где вы говорите в камеру (можно несколько файлов и дублей), и/или озвучку голосовым сообщением или аудиофайлом. Речь здесь бот расшифровывает.
2. **Этап «Перебивки».** Нажмите «🎞 Дальше — перебивки» (или `/broll`) и присылайте продукт, процесс, место. Бот только описывает планы, речь не разбирает. Вернуться к речи — «🎤 Дальше — речь» или `/talk`.
   Если файл попал не в тот этап — `/broll 3` сделает исходник 3 перебивкой, `/talk 3` — видео с речью (его расшифруют).

Какие сочетания понимает бот:
   - **речь в кадре + перебивки** — классика: ваша речь, поверх — перебивки по смыслу;
   - **озвучка + перебивки** — основа ролика закадровый голос, видеоряд подбирается под каждую фразу;
   - **речь в кадре + озвучка + перебивки** (гибрид) — в сценарий идут фразы обоих видов: вы в кадре говорите своё, под закадровые фразы подставляются планы. Озвучка не мешает речи из видео: бот не накладывает их друг на друга, а чередует;
   - **только видео без речи** — ролик из картинки в вашем темпе, с живым звуком или тишиной под музыку.
   Если в видео этапа «Речь» речи на самом деле нет, бот это поймёт сам и использует его как перебивку.

3. По желанию напишите, каким должен быть ролик: «на 30 секунд, начни с цены».
4. Нажмите «🎬 Смонтировать». Бот покажет прогноз расхода на ИИ (в долларах) и спросит «Запускаем?». Через несколько минут придёт готовый ролик.
5. Правки — обычным сообщением: «убери вторую фразу», «субтитры крупнее», «больше перебивок». Бот пересоберёт ролик. Кнопка «↩️ Прошлый вариант» вернёт предыдущую версию.
6. Под каждым вариантом написано, сколько потрачено на ИИ именно на него и сколько всего по ролику. Прогноз — оценка: реальный расход может отличаться.
7. Следующий ролик — `/new` или кнопка «🆕 Новый ролик». Исходники прошлого ролика удаляются.

Что бот делает при монтаже:
- выбирает лучший дубль каждой мысли и выкидывает оговорки и обрывы;
- вырезает паузы в речи длиннее 0,4 с;
- ставит перебивки по смыслу сказанного;
- делает наезды на говорящего, если так у вас в паспорте;
- вшивает субтитры по словам — цвет, размер, место и выделение слов берутся из паспорта;
- выравнивает громкость под соцсети;
- если перебивка снята на 60 кадров в секунду и больше, может плавно замедлить её вдвое (120 fps — вчетверо): продлить удачный кадр, закрыть нехватку видео, подчеркнуть деталь. Речь в кадре не замедляется. Снимайте перебивки в 60 fps — это даёт боту ещё один приём;
- кадр — как в ваших примерах (обычно вертикальный 1080×1920).

Музыку бот пока не добавляет — её удобнее поставить в Instagram при публикации.

Команды: `/status` — что загружено и сколько потрачено на ИИ, `/style` — паспорт, `/new` — новый ролик, `/edit` и `/learn` — режимы, `/broll` и `/talk` — этап загрузки (с номером — переназначить исходник), `/del 3` — убрать пример или исходник, `/reset` — удалить всё.

## Необязательные переменные

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `ALLOWED_USERS` | пусто | Номера пользователей Telegram через запятую, кому разрешён доступ. Если задано — правило «первый /start» не действует |
| `GEMINI_MODEL` | `gemini-3.8-flash` | Модель ИИ. Дешевле: `gemini-3.1-flash-lite` |
| `GEMINI_FALLBACK_MODEL` | `gemini-3.1-flash-lite` | Запасная модель, когда основная перегружена. Пустое значение — не переключаться |
| `TOK_PER_SEC` | `70` | Сколько токенов Gemini тратит на секунду видео — для прогноза расхода |
| `PRICE_IN` / `PRICE_OUT` | `0.75` / `3.75` | Цена 1 млн входных / выходных токенов, $. Нужна для подсчёта расхода |
| `AI_PARALLEL` | `3` | Сколько исходников ИИ разбирает одновременно |
| `SCENE_THRESHOLD` | `0.3` | Чувствительность поиска склеек в примерах. Меньше — находит больше |
| `PAUSE_MAX` | `0.4` | Паузы в речи длиннее этого (в секундах) вырезаются |
| `MAX_SOURCE_SEC` | `1800` | Предельная длина одного исходника, секунд |
| `MAX_PROJECT_SEC` | `3600` | Предельная длина всех исходников ролика вместе, секунд |
| `SUB_FONT` | `Montserrat ExtraBold` | Шрифт субтитров. Если его нет — берётся DejaVu Sans |
| `DATA_DIR` | путь Volume | Где хранить данные |

## Что важно знать

- При первом запуске бот переключается с общего сервера Telegram на свой. Вернуться на общий можно не раньше чем через 10 минут.
- Без `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` бот тоже работает, но принимает файлы только до 20 МБ и отправляет ролики до 50 МБ.
- Пока бот работает, в шапке чата видно «печатает…», а в сообщении со статусом идёт таймер. Если серверы Google перегружены, бот сам ждёт, повторяет и при необходимости переключается на запасную модель.
- Если сервер перезапустился посреди работы, бот сам продолжит приём и разбор файлов, а прерванный монтаж предложит запустить заново.
- Ролики и исходники отправляются в Gemini на разбор и сразу после него удаляются с серверов Google.
- Время слов в субтитрах рассчитывается по длине слов внутри фразы: фраза целиком попадает точно, отдельные слова — приблизительно.
- Volume на 5 ГБ: исходники одного ролика до ~3 ГБ помещаются. Если места мало, бот предупредит.
